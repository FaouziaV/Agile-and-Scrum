# Day 4 – Doing Scrum – Sprint Simulation

**Topics covered:** Sprint Planning · Daily Stand-up · Backlog Refinement · Sprint Review and Retrospective · Agile and DevOps Culture · Distributed Teams

This day focuses on applying Scrum practices through sprint simulations, managing dependencies and mid-sprint scope changes, and using retrospectives and DevOps practices to improve delivery.

## Set 1 – Digital Wallet Application – Mid-Sprint Change

### Business Scenario
A fintech team of five developers is working in a 10-day sprint. Previous sprint velocities were 21, 24, and 23 story points. On Day 4, the business requests a refund-to-wallet feature.

### Tasks
1. Calculate the average velocity, select backlog stories to match it, and write a measurable Sprint Goal.
2. Break three selected stories into tasks with hour estimates and record them on the sprint board.
3. Write Day 3 daily stand-up updates (yesterday, today, impediment) for three team members.
4. Re-prioritize the backlog after the refund-to-wallet request. State what is added, removed, and who makes the decision.
5. Prepare a 10-day sprint burndown from the supplied completed-points table and interpret the trend.
6. Write the retrospective (what went well, what to improve, and two action items with owners) and map the Definition of Done to a build pipeline (build, test, review, merge).

### Deliverables
- Sprint backlog
- Impediment log
- Burndown chart
- Retrospective actions
- Half-page pipeline mapping

## Set 2 – Airline Web Check-in – Blocked Dependency

### Business Scenario
An airline's web check-in team is mid-sprint when the payment-gateway sandbox needed for the seat-upgrade story becomes unavailable.

### Tasks
1. Compute team capacity (six members, eight working days, 70% focus factor) and decide the number of points to commit.
2. Write the Sprint Goal and select stories; document the Definition of Ready check for each selected story.
3. Log the impediment (description, impact, owner, escalation path, expected resolution) and show how the Scrum Master would remove it.
4. Run a refinement session on next sprint's top five stories: split one oversized story and re-estimate it.
5. Prepare the Sprint Review agenda and demonstration script against acceptance criteria.
6. Prepare one written, asynchronous stand-up for a distributed team across two time zones and compare it with a live stand-up.

### Deliverables
- Impediment log
- Sprint plan
- Sprint Review agenda
- Written asynchronous stand-up

## Set 3 – E-Learning Platform – Scope Change Handling

### Business Scenario
An e-learning company's team is on Day 6 of a 10-day sprint when the Product Owner requests a certificate-download feature for an upcoming launch.

### Tasks
1. Using the supplied backlog and velocity of 30 points, plan the sprint and state the Sprint Goal.
2. Analyse the impact of the new request on the sprint: what can be swapped out, what must wait, and how the Sprint Goal is protected.
3. Write stand-up statements for a developer blocked by a missing API contract and the Scrum Master's follow-up action.
4. Calculate sprint velocity from the completed-points table where one story is 80% done, and explain how partially completed work is counted.
5. Facilitate a retrospective using Start-Stop-Continue and produce three SMART action items.
6. Explain briefly how automation (unit tests, linting, pipeline) supports the Definition of Done.

### Deliverables
- Sprint plan
- Change-impact note
- Velocity calculation
- Retrospective actions

## Key Scrum Practices
- **Sprint Planning:** Establish the Sprint Goal, select work based on capacity and priority, and agree on a plan.
- **Daily Stand-up:** Inspect progress toward the Sprint Goal and identify blockers.
- **Backlog Refinement:** Clarify, split, prioritize, and estimate upcoming work.
- **Sprint Review:** Demonstrate completed work and gather stakeholder feedback.
- **Sprint Retrospective:** Identify improvements and commit to practical action items.
- **Definition of Done and automation:** Build, test, review, and merge practices help ensure work meets the team's quality standard.
