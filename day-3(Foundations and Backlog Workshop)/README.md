# Day 3 – Agile and Scrum: Foundations and Backlog Workshop

## Overview

This assignment focuses on Agile principles, Scrum roles, events and artifacts, and practical backlog creation and estimation. It includes three business scenarios that apply user stories, INVEST, acceptance criteria, prioritisation, Planning Poker, Jira setup, and team readiness/completion definitions.

## Topics Covered

- Agile overview and Agile vs. Waterfall
- Scrum roles, events, and artifacts
- Product vision and stakeholder mapping
- Epics and user stories (`As a / I want / so that`)
- INVEST checklist and story splitting
- Given / When / Then acceptance criteria
- MoSCoW prioritisation and business value vs. effort
- Fibonacci story points and Planning Poker
- Jira backlog, board, and story states
- Definition of Ready (DoR) and Definition of Done (DoD)

## Assignment Sets

### Set 1 – Online Grocery Delivery Application

A regional supermarket chain is building a grocery ordering and home-delivery application and needs a prioritised, estimated backlog before Sprint 1.

**Tasks:**
1. Create a product vision and identify the three Scrum roles, including one anti-pattern for each.
2. Define at least three epics and create 12 user stories.
3. Apply INVEST to every story and rewrite at least two stories that fail the checklist.
4. Write Given / When / Then acceptance criteria for five stories, including a negative scenario.
5. Prioritise stories with MoSCoW and estimate them using Fibonacci Planning Poker; explain the reference story.
6. Publish the epics and stories in Jira and record the DoR and DoD.

**Deliverables:** Jira board screenshot/export, backlog table with story/priorities/points, and DoR/DoD document.

### Set 2 – Insurance Claims Portal

An insurance company is creating a customer self-service portal to lodge claims, upload supporting documents, and track settlement status.

**Tasks:**
1. Draft a product vision and a brief Waterfall-vs-Agile comparison explaining why Agile fits.
2. Create four epics—Claim Registration, Document Upload, Claim Tracking, Settlement Notifications—and 12–14 user stories.
3. Review stories using INVEST and split oversized stories vertically.
4. Write Given / When / Then acceptance criteria for Claim Registration stories, including a validation failure.
5. Estimate stories using Planning Poker (1, 2, 3, 5, 8, 13); record outlier discussion and total backlog points.
6. Set up Jira with the board, epics, To Do / In Progress / In Review / Done statuses, and the DoD.

**Deliverables:** Jira board export, estimated backlog, and a one-page note on Scrum roles, events, and artifacts.

### Set 3 – Hospital Appointment Booking Application

A hospital group wants a mobile app for booking, rescheduling, and cancelling doctor appointments, with reminder notifications.

**Tasks:**
1. Write the product vision, list stakeholders, and map them to Product Owner, Scrum Master, Developer, or Customer.
2. Create epics for Booking, Rescheduling and Cancellation, Reminders, and Doctor Schedule Management, with at least 12 stories.
3. Apply INVEST and rewrite stories that are not independent or testable.
4. Write Given / When / Then acceptance criteria for booking and cancellation, including a slot-already-taken scenario.
5. Prioritise by business value vs. effort, run Planning Poker, and explain story points vs. hours.
6. Publish the Jira backlog and define at least six DoR and six DoD checklist items.

**Deliverables:** Prioritised backlog, Jira board screenshot, and DoR/DoD checklist.

## Tools

- Jira for epics, stories, backlog prioritisation, estimation, and sprint/board tracking
- Planning Poker / Fibonacci scale for relative estimation
- Markdown or Word document for DoR and DoD checklists

## Learning Outcome

Practice translating business needs into small, valuable, testable user stories, prioritising and estimating backlog work, and preparing a Jira backlog that is ready for sprint planning.
